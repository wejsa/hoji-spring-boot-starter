## 3. 공통 패턴 (cross-task)

### Keep (반복하면 좋은 것)
- **표준 체이닝 이탈 0회**: 7 Task × (plan→impl→review→merge / 남은 스텝 merge→impl --next) 전부 정상 흐름. 빌드 3회 실패·CRITICAL 미해결·승인 불가 중단 0건.
- **스텝 단위 PR 분할**: 13 PR 전부 라인 제한 내, 단일 스텝 = 단일 PR로 리뷰 단위가 작고 일관됨.
- **마이그레이션/버그 규칙 추적성**: M1~M9·B1~B5·결합제거 규칙이 Task description에 명시되어 누락 없이 반영(B1~B2 HOJI-003, B3 HOJI-002, B5 HOJI-006, M1·M9 HOJI-004, M2·M3 HOJI-006).

### Learn (이번에 드러난 사실)
- **슬라이스 테스트 녹색 ≠ 조립 정상**: HOJI-005의 `@DataJpaTest`/슬라이스는 통과했으나, 동일 코드의 잠재 결함 2건이 **HOJI-007 통합 스모크(전체 컨텍스트 기동)** 단계에서야 드러남:
  1. `SequenceAutoConfiguration` — `@ConditionalOnSingleCandidate(DataSource)` 평가 순서 미고정 → 0 후보 판정 → 채번 빈 누락.
  2. `OracleSequenceRepository` — Kotlin `final` + CGLIB(`proxyTargetClass=true`)에서 메서드 레벨 `@Transactional`이 all-open을 발동 못 시켜 프록시 생성 실패.
  → **소비자 관점 조립 검증은 모듈별 테스트로 대체 불가**. (lessons L-001·L-002·L-003)

### Improve (다음에 보완할 것)
- **스모크가 빈 *존재*만 단언** — 프록시/트랜잭션 실제 경로·deny-by-default 401 등 *행위*를 행사하지 않아, 컨텍스트 기동 회귀는 잡아도 런타임 결함은 놓침. (lessons L-004)
- **auto-config 순서 지정 방식 불일치** — jpa는 클래스 리터럴 `@AutoConfiguration(after=…)`, security는 문자열 `beforeName`. 동작은 같으나 규칙 혼재 = 유지보수 부채.
- **README 라이선스 표기 불일치** — README 하단 `MIT` ↔ POM `Apache-2.0`. 소비자 혼란 소지.
